# HLS受信の同時接続試験（2026年10月29日）

Mac一台から独立したHTTPS接続でHLSプレイリストと映像セグメントを取得しました。ChilloutVRやAVProそのものを25個起動した試験ではありません。映像のデコード、実機のバッファ制御、多拠点からの接続は未検証です。受信URL・プレイリスト・映像本体は記録していません。

配信の実測ビットレートは約10.36 Mbpsでした。25人分には約259 Mbpsと通信の余裕が必要です。利用者申告のMac下り速度は約286 Mbpsですが、別の速度測定先での値なので、このVPSまでの経路速度を保証しません。

試験後、利用者がVPSの上りを別途測定し **94.03 Mbps** と確認しました。今回の80〜90 Mbpsという受信の頭打ちと整合します。この上りを前提とすると、HLSだけの単純計算で約9人が上限で、余裕を含めると7〜8人程度です。ポータル映像もVPSから各人へ送るならその分を加算します。追加2 Mbps／人なら7人で約86.5 Mbps、8人で約98.9 Mbpsとなり、8人は上り測定値を超えます。

## 段階試験

1、5、10、20人を各15秒、25人を90秒実行し、自動停止しました。

|人数|区間平均の受信速度|完了セグメント|映像時間より取得が遅かったもの|
|---:|---:|---:|---:|
|1|17.85 Mbps|6|0|
|5|57.70 Mbps|20|0|
|10|77.90 Mbps|27|13|
|20|69.30 Mbps|24|22|

各区間が短く、参加直後には直近2セグメントも取得するので、区間速度は定常ビットレートと一致しません。25人区間の終了直前に中断された取得を初回集計が完了扱いにしていたため、停止処理を修正して次の確認試験を別途実行しました。初回の生レポートも残しています。

## 25人の確認試験

25クライアントを60秒間同時稼働させた再試験でも不足を再現しました。

|指標|結果|
|---|---:|
|平均受信速度|83.17 Mbps|
|転送量|約624 MB|
|正常完了した映像セグメント|109|
|取得時間が映像時間を超過|109 / 109|
|セグメント取得時間の中央値|12.272秒|
|セグメント取得時間の95パーセンタイル|16.200秒|
|HTTP 404|35件|
|プレイリストの先頭に追い越されたセグメント|96|
|配信ビットレート|10.36 Mbps|

セグメントは約4.17秒です。取得に12〜16秒かかるため、25人分のリアルタイム受信は維持できません。404は遅れたセグメントがサーバーの保持範囲から消えた状況と整合しますが、サーバー上のログとの照合はしていません。

**この経路では25人同時視聴に合格していません。** 5人の短時間試験は遅延なしでしたが、5人の長時間安定稼働まで保証する試験ではありません。約80〜90 Mbpsの頭打ちがVPSの送信帯域、ネットワーク経路、同一IPへの制限、Mac側の回線のどれによるものかは未確定です。nginx設定のソースを検索した範囲では `limit_rate` / `limit_conn` は見つかりませんでした。実サーバーの有効設定、NIC送信量、CPU、TCP再送、契約帯域と、別回線からの同時試験での切り分けが必要です。

## 再実行と停止

リポジトリーのルートから:

```sh
.venv/bin/python cvxr/castle-of-ideas/tools/hls-load-test.py
```

通常は約150秒で終了します。Ctrl+CまたはSIGTERMで中断しても集計を保存します。最大25クライアント、転送量6 GBで停止する上限があります。URLは `streaming.local.json` から読み、コンソールや結果に出しません。

25人だけを60秒確認する場合:

```sh
.venv/bin/python cvxr/castle-of-ideas/tools/hls-load-test.py \
  --single-clients 25 --hold-seconds 60 \
  --report-dir cvxr/castle-of-ideas/build/hls-load-test-confirmation
```

結果はGit管理外の `build/hls-load-test/summary.json` と `build/hls-load-test-confirmation/summary.json` に保存しています。試験はどちらも終了済みで、負荷は残っていません。
